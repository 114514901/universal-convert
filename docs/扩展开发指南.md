# UniversalConvert 扩展开发指南

本文面向想要给 UniversalConvert 新增转换能力的开发者。核心设计目标是：**新增一种格式/转换器 = 新增一个插件 DLL，主程序与右键菜单零改动。**

插件分两种分发形态，契约完全相同：

- **内置插件**：随主程序安装包分发（`{安装目录}\plugins\`）。
- **在线扩展**：发布到扩展仓库，用户在应用内「扩展中心」安装/更新/卸载（免管理员，装到 `%AppData%\UniversalConvert\plugins`）。

## 1. 架构总览

```
主仓库 src/
├── UniversalConvert.Core/            # 抽象层（插件契约、引擎、格式注册表、错误解析、配置）
│   ├── Plugins/                      # IConverterPlugin、IPreviewProvider、OptionDefinition 等
│   ├── Engine/                       # ConversionEngine、FormatRegistry、PresetMerger
│   ├── Models/                       # ConversionRequest/Result/Progress
│   ├── Process/                      # ProcessRunner、ExternalToolConverterBase
│   ├── Diagnostics/                  # ErrorParser（错误分类）
│   └── Config/                       # AppConfig、ConfigStore（%AppData% 下的 JSON）
├── UniversalConvert.App/             # WPF 壳（主界面 + 动态表单 + 无界面转换 + 扩展中心）
├── UniversalConvert.ContextMenu/     # SharpShell 动态右键菜单
└── UniversalConvert.Installer/       # 右键菜单注册/卸载

扩展仓库（universal-convert-extensions）
└── plugins/{插件目录}/               # 每个扩展一个目录：源码 + manifest.json
    └── .github/workflows/build.yml   # 打 tag {目录名}-{版本} 自动构建并发布 zip
```

数据流：插件声明能力 → `FormatRegistry` 汇总 → 主界面与右键菜单自动感知 → 用户选择格式/预设 → `PresetMerger` 合并参数 → 插件 `ConvertAsync` 执行。

## 2. 插件契约

所有插件实现 `UniversalConvert.Core.Plugins.IConverterPlugin`：

```csharp
public interface IConverterPlugin
{
    string Id { get; }              // 唯一标识，如 "com.universalconvert.xxx"
    string Name { get; }            // 显示名
    string Description { get; }
    string Version { get; }         // 插件自身版本，如 "1.0.0"
    string MinAppVersion { get; }   // 最低可运行应用版本（可 null）
    string MaxAppVersion { get; }   // 最高已知可用应用版本（可 null）

    void Initialize(IPluginContext context);          // 加载后注入宿主环境
    IList<ConversionCapability> GetCapabilities();     // 声明能力（纯声明，无副作用）
    bool IsToolAvailable();                            // 外部工具是否可用
    Task<ConversionResult> ConvertAsync(ConversionRequest req, IProgress<ConversionProgress> p, CancellationToken ct);
}
```

### MinAppVersion 是硬约束

`MinAppVersion` 声明插件可运行的最低应用版本（SemVer，如 `"1.7.3"`）。**插件加载时强制校验**：当前应用版本低于要求时，该插件会被跳过加载，并在扩展管理器「加载错误」区显示友好提示（而不是等插件功能运行时报反射/接口错误）。应用版本取自仓库根目录 `Directory.Build.props` 的 `<Version>`，两个仓库的构建同源。

- 依赖新 API 的扩展必须声明 `MinAppVersion`，否则在老版本应用上会加载失败或运行异常。
- 扩展中心安装页也会根据 `minAppVersion` 显示「应用版本过低」警告并阻止问题安装。
- `MaxAppVersion` 仅作提示（「未验证」），不阻止加载。

> ⚠️ **关键约束**：`GetCapabilities()` 必须是"纯"的（只返回静态声明，不得加载原生库/启动进程）。因为右键菜单会把插件加载进 explorer.exe，纯声明才能保证菜单秒开、不拖垮资源管理器。所有重活只发生在 `ConvertAsync`（主程序进程）。

### 两种典型实现方式

**A. 外部命令行工具类**（如 ffmpeg、pandoc）——继承 `ExternalToolConverterBase`：

```csharp
public sealed class MyPlugin : ExternalToolConverterBase
{
    public override string Id => "com.universalconvert.my";
    public override string Name => "MyTool";
    public override string Description => "...";
    protected override string ToolName => "mytool";       // 通过 FindTool 定位

    public override IList<ConversionCapability> GetCapabilities() { /* 见 §4 */ }
    protected override string BuildArguments(ConversionRequest req, string outputPath) { /* 命令行 */ }
    protected override void OnOutputLine(string line, ...) { /* 可选：解析进度 */ }
}
```

基类已封装：找工具 → 生成输出路径 → 跑进程 → 错误码判断 → 结果封装。工具定位优先级：`config.json` 的 `ToolPaths` → 安装目录 `{安装目录}\tools\` → 系统 PATH。**插件自带的工具**（`{插件DLL目录}\tools\{工具名}.exe`）优先于上述所有路径——在线扩展的工具二进制随 zip 分发，天然命中此规则。

**B. 纯 C# 内置实现**（如 NCM 解密）——直接实现 `IConverterPlugin`，`IsToolAvailable()` 返回 `true`。

**C. 自定义多步流程**（如 MIDI：FluidSynth 渲染 wav → ffmpeg 链式转码）——直接实现 `IConverterPlugin`，在 `ConvertAsync` 里自行编排多个外部工具（复用 `ProcessRunner` 或 `Process.Start`）。

## 3. 可选接口：IPreviewProvider（文件预览）

除转换外，插件还可以提供**预览渲染**能力。主程序预览窗口按「提供者优先」策略工作：某个输入扩展名若有插件声明支持预览，先调用渲染接口生成可播放的音频文件再播放；渲染失败或没有提供者时，回退到播放器直接打开，最后回退到 ffmpeg 转码。

典型场景：MIDI 文件（`.mid`/`.midi`）无法直接播放，由 MIDI 扩展用 FluidSynth 合成音色库渲染成 wav 再播放。

```csharp
public interface IPreviewProvider
{
    /// <summary>支持的预览输入扩展名（小写、含点，如 ".mid"、".midi"）。</summary>
    IList<string> SupportedPreviewExtensions { get; }

    /// <summary>
    /// 把输入文件渲染为可播放的音频文件（通常为 WAV）。
    /// 返回生成文件的绝对路径；失败返回 null（调用方回退到其它预览方式）。
    /// 返回的临时文件由调用方负责删除，插件不得自行清理。
    /// </summary>
    Task<string> RenderPreviewAsync(string inputPath, CancellationToken cancellationToken);
}
```

一个类可同时实现 `IConverterPlugin` 与 `IPreviewProvider`：

```csharp
public sealed class MidiPlugin : IConverterPlugin, IPreviewProvider
{
    public IList<string> SupportedPreviewExtensions =>
        new List<string> { ".mid", ".midi" };

    public async Task<string> RenderPreviewAsync(string inputPath, CancellationToken ct)
    {
        // 用 Fluidsynth 渲染到临时 wav 并返回路径
        var wav = Path.Combine(Path.GetTempPath(), "uc-midi-" + Guid.NewGuid().ToString("N") + ".wav");
        // ... 运行 fluidsynth，失败返回 null
        return File.Exists(wav) ? wav : null;
    }
}
```

预览渲染同样要求**廉价启动**：只负责把输入变成可播放音频，不得弹出窗口、不得写配置。

## 4. 声明能力（GetCapabilities）

```csharp
public override IList<ConversionCapability> GetCapabilities()
{
    return new List<ConversionCapability>
    {
        new ConversionCapability
        {
            InputExtension = ".mp4",
            InputDisplayName = "MP4 视频",
            Outputs = new List<OutputFormat>
            {
                new OutputFormat { Extension = ".mp3", DisplayName = "MP3 音频" }
            }
        }
    };
}
```

`InputExtension` 决定右键菜单/主界面是否支持该文件；`Outputs` 决定能转出哪些格式。

### 格式冲突与选择记忆（FormatResolver）

多个插件可能注册**同一方向**的转换（如两个插件都支持 `.md` → `.pdf`）。此时：

1. 转换前弹出「格式选择」窗口列出候选插件，用户选择后按「不再提醒」可记住该选择（记忆存于设置 `formatChoice.{输入扩展}.{输出扩展}`，以插件 Id 为值）。
2. 已记住的插件被卸载后自动回退到重新询问。
3. 用户可在 **设置 → 高级 → 清除格式选择记忆** 一键清除全部记忆。

插件侧无需任何处理，但要保证 `Id` 稳定（卸载/重装后记忆才能正确关联）。

## 5. 参数与预设

- **`OutputFormat.Options`**：可编辑参数的 schema（`OptionDefinition`），供动态表单自动渲染控件（枚举→下拉、布尔→勾选、数值/文本→文本框），无需为每种格式硬编码界面。
- **`OutputFormat.Presets`**：命名参数集（`ConversionPreset`），右键菜单里以子菜单展示。
- **合并顺序**：`默认值 → 预设覆盖 → 用户手改覆盖`，由 `PresetMerger.Merge()` 统一为最终 `Options` 字典，插件只消费 `Options`。

```csharp
// 参数 schema
new OptionDefinition {
    Key = "videoBitrate", Label = "视频码率", Type = OptionType.Enum,
    DefaultValue = "4000k",
    Choices = { new OptionChoice { Value = "2000k", Label = "2000 kbps" } }
}
// 预设
new ConversionPreset { Name = "高清 1080p", Options = { ["scale"] = "1920:1080" } }
```

有 `Options` 或 `Presets` 的格式，右键菜单里会显示「默认（推荐） + 各预设 + 更多设置...」；两者皆无则直接点击即转。

## 6. 结果与错误

返回 `ConversionResult`：成功时 `Success=true` + `OutputPath`；失败时填 `ErrorMessage`（摘要）与 `FullError`（完整 stdout/stderr，供错误解析与"复制报错"）。

`Diagnostics/ErrorParser` 把常见报错（未知编码器、文件不存在、权限不足、磁盘满、输入损坏等）归类为 `ConversionErrorKind`，UI 据此给出本地化建议。若你的工具报错有独特模式，可在 `ErrorParser.Parse` 里追加正则规则。

## 7. 新增一个插件的完整步骤

### 路径 A：内置插件（随主程序分发）

1. 新建类库项目（net48），`ProjectReference` 到 `UniversalConvert.Core`。
2. 实现 `IConverterPlugin`（或继承 `ExternalToolConverterBase`），可选实现 `IPreviewProvider`。
3. 把项目加进 `UniversalConvert.sln`。
4. 在 `.github/workflows/build.yml` 的「Assemble dist」步骤加一行，把该插件 DLL 拷进 `dist\plugins\`。
5. 打 tag 触发 CI，产出安装包；插件 DLL 会被装到 `{安装目录}\plugins\`，主程序/右键菜单自动发现。

### 路径 B：在线扩展（扩展仓库分发，推荐）

1. 在 [universal-convert-extensions](https://github.com/114514901/universal-convert-extensions) 仓库 `plugins\{目录名}\` 下新建扩展：源码 + `manifest.json` + 可选 `tools\` 工具二进制（构建时由 CI 生成）。
2. 在 `index.json` 的 `plugins` 数组追加一条记录。
3. 打 tag `{目录名}-{版本}`（如 `MIDI-1.0.0`），CI 自动：下载 Core SDK → 编译插件 → 执行该插件的工具构建步骤 → 打包 zip → 发 GitHub Release。
4. 用户在应用内「扩展中心」即可看到并安装。

**manifest.json**（`Core.Plugins.PluginManifest`）：

```json
{
  "id": "com.universalconvert.midi",
  "name": "MIDI",
  "description": "MIDI 合成与音频转换（FluidSynth + 音色库随包分发）",
  "version": "1.0.0",
  "author": "UniversalConvert",
  "minAppVersion": "2.0.2",
  "maxAppVersion": null,
  "homepage": "https://www.fluidsynth.org/"
}
```

**index.json** 记录（扩展中心的目录项）：

```json
{
  "id": "com.universalconvert.midi",
  "name": "MIDI",
  "description": "…",
  "version": "1.0.0",
  "author": "UniversalConvert",
  "minAppVersion": "2.0.2",
  "maxAppVersion": null,
  "homepage": "…",
  "downloadUrl": "https://github.com/114514901/universal-convert-extensions/releases/download/MIDI-1.0.0/MIDI-1.0.0.zip"
}
```

`downloadUrl` 遵循 `releases/download/{目录名}-{版本}/{目录名}-{版本}.zip` 约定，与 CI 产物一致。

### 扩展包格式与生命周期

- **安装位置**：`%AppData%\UniversalConvert\plugins\{Name}\`（免管理员）。与内置插件合并加载，**同 Id 时用户目录优先**（可覆盖/升级内置插件）。
- **zip 结构**：`manifest.json` + 插件 DLL + 可选 `tools\` 工具二进制（由 `PluginPackage` 读写/解压）。
- **更新/卸载与重启暂存**：已加载的插件 DLL 被进程锁定（.NET Framework 的文件共享模式），无法直接覆盖/删除。因此：
  - 更新：解压失败时自动暂存到 `%AppData%\UniversalConvert\pending\`，重启后（插件加载前）自动搬入生效。
  - 卸载：删除失败时写入 `pending-uninstall` 标记，重启后自动删除。
  - 需要重启的操作（含首次安装）会弹出「重启应用」提示（`AppRestart.PromptAndRestart()`）。
- **扩展管理器**（设置/主界面入口）：展示插件来源（内置/扩展）、版本、兼容性警告与加载错误；可卸载用户扩展、单插件检查更新、批量检查更新（并行）。
- **兼容性检查**：安装/更新前按 `minAppVersion`/`maxAppVersion` 校验；`MinAppVersion` 不满足时拒绝并提示。

## 8. 设置系统

设置采用「schema + 通用界面」架构，新增设置无需改 UI：

- **设置项定义**：`Core.Config.SettingDefinition`（Key / Category / Label / Description / Type / DefaultValue / Choices）。
- **持久化**：`AppConfig.Settings`（字典），随 `config.json` 一起读写。
- **应用级设置**：在 `App.SettingsRegistry.All` 里追加一条 `SettingDefinition` 即可。
- **插件自定义设置**：插件实现 `ISettingsContributor` 接口（`GetSettings()` 返回定义列表），设置界面自动收录；插件通过 `IPluginContext.GetSetting(key, defaultValue)` 读取值。
- **设置界面**：`App.SettingsWindow` 根据定义动态渲染（枚举→可编辑下拉、布尔→勾选、文本→输入框），按 `Category` 分组。

```csharp
// 插件声明并读取设置
public sealed class MyPlugin : IConverterPlugin, ISettingsContributor
{
    public IList<SettingDefinition> GetSettings() => new List<SettingDefinition>
    {
        new SettingDefinition { Key = "my.quality", Label = "质量", Type = OptionType.Enum,
            DefaultValue = "high", Choices = { new OptionChoice { Value = "high", Label = "高" } } }
    };
    // 在 ConvertAsync 中：var q = context.GetSetting("my.quality", "high");
}
```

## 9. 本地化

- 应用 UI 字符串在 `src/UniversalConvert.App/Localization/Strings.resx`（中文，中性）与 `Strings.en.resx`（英文），经 `Strings` 静态类访问，按系统 UI 语言自动切换。
- **插件元数据（格式名、参数标签、预设名、设置标签）默认单语言（中文）**，直接写中文字面量即可。
- **`@资源键` 国际化钩子**：标签若以 `@` 开头，会被当作应用资源键解析（`Strings.L`），命中应用 resx 时自动本地化，未命中则原样显示。适用于想复用应用内置文案（如 `@Original` = 「原始」）的场景；自定义文案请勿使用 `@` 前缀，否则会显示原始键名。

## 10. 构建、版本与发布

- **版本**：主程序版本统一在根目录 `Directory.Build.props` 的 `<Version>`；发新版本改这里 + 打 tag。
- **双通道**：正式版 tag 为 `vX.Y.Z`（非 prerelease），开发版 tag 为 `vX.Y.Z-dev.N`（GitHub 上标记为 prerelease）。旧版本/正式版用户通过 `/releases/latest` 只会看到正式版，不受开发版影响。
- **主仓库 CI**：push 到 `main` 自动编译；打 `v*` tag 触发「拉 ffmpeg → 组 dist → Inno Setup 打包 → 发 GitHub Release」，并把含 `-` 的 tag 自动标记为 prerelease。
- **扩展仓库 CI**：tag `{目录名}-{版本}` → 下载 Core SDK（`UniversalConvert.Core.SDK.zip`，主仓库每次 Release 附带）→ 编译 → 按插件执行工具构建步骤（如下载 pandoc、PyInstaller 打包 markitdown、下载 fluidsynth 与音色库）→ 组包发布。
- **注意**：GitHub Release 列表按 tag 字典序排序，同版本线的开发号请保持个位数（`dev.1`~`dev.9`），或换版本线（如 `2.0.2-dev.10` 会排在 `dev.2` 之前导致列表混乱）。
- **安装包**：`packaging/UniversalConvert.iss`，中英双语，安装时自动注册右键菜单并在完成页提供重启资源管理器。

## 11. 常见问题

- **右键菜单不出现**：多半是 explorer 未重启；重装时勾选完成页的"重启资源管理器"，或手动 `taskkill /f /im explorer.exe & start explorer.exe`。若仍不行，查看 `%AppData%\UniversalConvert\install.log`。
- **插件被跳过加载、扩展管理器提示「要求应用版本 >= …」**：应用版本过旧，升级应用（或降低插件的 `MinAppVersion`）。
- **ffmpeg 报"Unknown encoder"**：打包的是 GPL 版才含 libx264；若改用 LGPL 版需换默认编码器。
- **NCM 输出格式**：先解密成文件原格式（mp3/flac），若目标格式不同则再交给 FFmpeg 转码，故支持全部音频格式。
- **更新/卸载后要重启才生效**：插件 DLL 被进程锁定，属预期行为；重启应用即可（安装、更新、卸载流程都会自动提示）。
