# UniversalConvert 扩展开发指南

本文面向想要给 UniversalConvert 新增转换能力的开发者。核心设计目标是：**新增一种格式/转换器 = 新增一个插件 DLL，主程序与右键菜单零改动。**

## 1. 架构总览

```
src/
├── UniversalConvert.Core/            # 抽象层（插件契约、引擎、格式注册表、错误解析、配置）
│   ├── Plugins/                      # IConverterPlugin、OptionDefinition、ConversionPreset 等
│   ├── Engine/                       # ConversionEngine、FormatRegistry、PresetMerger
│   ├── Models/                       # ConversionRequest/Result/Progress
│   ├── Process/                      # ProcessRunner、ExternalToolConverterBase
│   ├── Diagnostics/                  # ErrorParser（错误分类）
│   └── Config/                       # AppConfig、ConfigStore（%AppData% 下的 JSON）
├── UniversalConvert.App/             # WPF 壳（主界面 + 动态表单 + 无界面转换）
├── UniversalConvert.ContextMenu/     # SharpShell 动态右键菜单
└── UniversalConvert.Installer/       # 右键菜单注册/卸载
plugins/                              # 各转换器插件（运行时被扫描加载）
├── UniversalConvert.Plugin.FFmpeg/   # 参考：外部命令行工具类插件
├── UniversalConvert.Plugin.Ncm/      # 参考：纯 C# 内置解密类插件
└── UniversalConvert.Plugin.Kgm/      # 参考：纯 C# 解密 + 密钥表分发类插件
```

数据流：插件声明能力 → `FormatRegistry` 汇总 → 主界面与右键菜单自动感知 → 用户选择格式/预设 → `PresetMerger` 合并参数 → 插件 `ConvertAsync` 执行。

## 2. 插件契约

所有插件实现 `UniversalConvert.Core.Plugins.IConverterPlugin`：

```csharp
public interface IConverterPlugin
{
    string Id { get; }              // 唯一标识，如 "com.universalconvert.xxx"
    string Name { get; }            // 显示名
    string Description { get; }

    void Initialize(IPluginContext context);          // 加载后注入宿主环境
    IList<ConversionCapability> GetCapabilities();     // 声明能力（纯声明，无副作用）
    bool IsToolAvailable();                            // 外部工具是否可用
    Task<ConversionResult> ConvertAsync(ConversionRequest req, IProgress<ConversionProgress> p, CancellationToken ct);
}
```

> ⚠️ **关键约束**：`GetCapabilities()` 必须是"纯"的（只返回静态声明，不得加载原生库/启动进程）。因为右键菜单会把插件加载进 explorer.exe，纯声明才能保证菜单秒开、不拖垮资源管理器。所有重活只发生在 `ConvertAsync`（主程序进程）。

### 两种典型实现方式

**A. 外部命令行工具类**（如 ffmpeg、pandoc）——继承 `ExternalToolConverterBase`：

```csharp
public sealed class MyPlugin : ExternalToolConverterBase
{
    public override string Id => "com.universalconvert.my";
    public override string Name => "MyTool";
    public override string Description => "...";
    protected override string ToolName => "mytool";       // 通过 FindTool 定位

    public override IList<ConversionCapability> GetCapabilities() { /* 见 §3 */ }
    protected override string BuildArguments(ConversionRequest req, string outputPath) { /* 命令行 */ }
    protected override void OnOutputLine(string line, ...) { /* 可选：解析进度 */ }
}
```

基类已封装：找工具 → 生成输出路径 → 跑进程 → 错误码判断 → 结果封装。工具定位优先级：`config.json` 的 `ToolPaths` → `{安装目录}\tools\` → 系统 PATH。把 `mytool.exe` 丢进 `tools\` 即自动可用。

**B. 纯 C# 内置实现**（如 NCM 解密）——直接实现 `IConverterPlugin`，`IsToolAvailable()` 返回 `true`。

## 3. 声明能力（GetCapabilities）

```csharp
public override IList<ConversionCapability> GetCapabilities()
{
    return new List<ConversionCapability>
    {
        new ConversionCapability
        {
            InputExtension = ".mp4",
            InputDisplayName = "MP4 视频",
            Outputs = new List<OutputFormat>
            {
                new OutputFormat { Extension = ".mp3", DisplayName = "MP3 音频" }
            }
        }
    };
}
```

`InputExtension` 决定右键菜单/主界面是否支持该文件；`Outputs` 决定能转出哪些格式。

## 4. 参数与预设

- **`OutputFormat.Options`**：可编辑参数的 schema（`OptionDefinition`），供动态表单自动渲染控件（枚举→下拉、布尔→勾选、数值/文本→文本框），无需为每种格式硬编码界面。
- **`OutputFormat.Presets`**：命名参数集（`ConversionPreset`），右键菜单里以子菜单展示。
- **合并顺序**：`默认值 → 预设覆盖 → 用户手改覆盖`，由 `PresetMerger.Merge()` 统一为最终 `Options` 字典，插件只消费 `Options`。

```csharp
// 参数 schema
new OptionDefinition {
    Key = "videoBitrate", Label = "视频码率", Type = OptionType.Enum,
    DefaultValue = "4000k",
    Choices = { new OptionChoice { Value = "2000k", Label = "2000 kbps" } }
}
// 预设
new ConversionPreset { Name = "高清 1080p", Options = { ["scale"] = "1920:1080" } }
```

有 `Options` 或 `Presets` 的格式，右键菜单里会显示「默认（推荐） + 各预设 + 更多设置...」；两者皆无则直接点击即转。

## 5. 结果与错误

返回 `ConversionResult`：成功时 `Success=true` + `OutputPath`；失败时填 `ErrorMessage`（摘要）与 `FullError`（完整 stdout/stderr，供错误解析与"复制报错"）。

`Diagnostics/ErrorParser` 把常见报错（未知编码器、文件不存在、权限不足、磁盘满、输入损坏等）归类为 `ConversionErrorKind`，UI 据此给出本地化建议。若你的工具报错有独特模式，可在 `ErrorParser.Parse` 里追加正则规则。

## 6. 新增一个插件的完整步骤

1. 新建类库项目（net48），`ProjectReference` 到 `UniversalConvert.Core`。
2. 实现 `IConverterPlugin`（或继承 `ExternalToolConverterBase`）。
3. 把项目加进 `UniversalConvert.sln`。
4. 在 `.github/workflows/build.yml` 的「Assemble dist」步骤加一行，把该插件 DLL 拷进 `dist\plugins\`。
5. 打 tag 触发 CI，产出安装包；插件 DLL 会被装到 `{安装目录}\plugins\`，主程序/右键菜单自动发现。

## 7. 本地化

- 应用 UI 字符串在 `src/UniversalConvert.App/Localization/Strings.resx`（中文，中性）与 `Strings.en.resx`（英文），经 `Strings` 静态类访问，按系统 UI 语言自动切换。
- 插件元数据（格式名、参数标签、预设名）目前为单语言（中文），尚未纳入国际化机制。

## 8. 构建、版本与发布

- **版本**：统一在根目录 `Directory.Build.props` 的 `<Version>`；发新版本改这里 + 打 `vX.Y.Z` tag。
- **CI**：push 到 `main` 自动编译；打 `v*` tag 额外触发「拉 ffmpeg → 组 dist → Inno Setup 打包 → 发 GitHub Release」。
- **安装包**：`packaging/UniversalConvert.iss`，中英双语，安装时自动注册右键菜单并在完成页提供重启资源管理器。

## 9. 常见问题

- **右键菜单不出现**：多半是 explorer 未重启；重装时勾选完成页的"重启资源管理器"，或手动 `taskkill /f /im explorer.exe & start explorer.exe`。若仍不行，查看 `%AppData%\UniversalConvert\install.log`。
- **ffmpeg 报"Unknown encoder"**：打包的是 GPL 版才含 libx264；若改用 LGPL 版需换默认编码器。
- **NCM 输出格式**：先解密成文件原格式（mp3/flac），若目标格式不同则再交给 FFmpeg 转码，故支持全部音频格式。
